## 论文数据与结果

IBSI 论文的核心产出是标准化提案：定义影像组学特征的数学口径、提供数字体模与参考值，并对参与软件的输出做一致性核验。

- 数据：IBSI 官方数字体模（含掩膜）与配套参考值，公开仓库发布。
- 任务：使用统一体模与统一特征定义，比对不同软件实现的特征输出。
- 评估方式：逐特征对照参考值，按容差判断一致性，并对不一致项给出原因分类（插值、离散化、滤波器口径、特征定义等）。
- 结果：论文报告了标准化特征集合与一致性核验结论；**具体数值与特征清单以原文和官方仓库为准**，本页不复述、不转抄。

本案例只取 2D 子集：参考手册 Chapter 3 的 169 张特征表中，144 个特征提供了 2D 参考值。其中 95 个纹理特征 / 408 行可直接用数字体模的 2D 聚合比对；49 个非纹理特征 / 98 行的 2D 参考值来自 CT 配置 A/B，必须额外引入对应 CT 数据才能比对；其余 25 个形态学特征只定义 3D 几何口径，不纳入 2D 比对。本轮范围已冻结为**只跑数字体模、不引入 CT 配置 A/B 数据**，因此 49 个非纹理特征明确排除在本轮之外。

## 工作流与算子

本案例的工作流由四类算子组成，参照协议只在需要时启用预处理：

| 顺序 | 算子 | 版本 | 作用 |
| --- | --- | --- | --- |
| 1 | `ReadImages` | 1.0.0 | 读取体模图像与掩膜，建立样本表 |
| 2 | `ImageFormatConversion` | 1.0.0 / 1.1.0 | 统一图像模式与掩膜二值化口径 |
| 3 | `Preprocessing2D` | 1.0.0 / 1.1.0 | 按参考协议做重采样与离散化等前置处理（仅在协议要求时启用） |
| 4 | `IBSI2DFeatureExtraction` | 1.0.0 | 提取 2D IBSI 特征（`original` 与协议要求的滤波器） |
| 5 | `IBSIReferenceComparison` | 1.0.0 | 把特征表与参考值表、映射表逐行对照，输出逐特征比对表与按族一致率 |

```text
ReadImages → ImageFormatConversion → Preprocessing2D（按协议）→ IBSI2DFeatureExtraction → IBSIReferenceComparison
```

`IBSIReferenceComparison` 的输入是特征表、参考值表（`code/name/family/dataset/aggregation/value/tolerance/consensus`）与映射表（`code/status/pyradiomicsClass/pyradiomicsFeature`），后两者可由 `packages/compliance/ibsi-2d/` 下的 CSV 经 `ReadTable` 读入。容差规则写在算子里、不可配置：有容差判 `pass`/`fail`，无容差标记 `no_tolerance` 且不计入一致率分母，因此不存在「调阈值让结果变好」的空间。`recordAggregation=per_slice_mean` 只在 `aggregation=2D` 时允许使用；`2D, averaged` 与 `2D, slice-merged` 需要矩阵级聚合，算子会直接拒绝逐层均值，避免把不可重建的口径算成通过。

算子版本以上表为准；若运行时的算子目录版本不同，以复现包内的算子清单为最终依据。

## 方法差异

| 维度 | 原文 / 参考协议 | 本次复现 | 影响方向 |
| --- | --- | --- | --- |
| 输入通道 | 数字体模按协议定义的灰度与位深 | 平台读取后的图像模式与位深（待运行记录确认） | 方向不明：位深或缩放不一致会改变离散化与纹理特征 |

## 局限性

- **自证限制**：PyRadiomics 是 IBSI 的参与软件之一，本次校验本质上是「参与软件对照官方参考值」，不能视为独立第三方验证。案例页与任何对外材料都必须写明这一关系。
- **只覆盖 2D 子集**：169 张特征表中仅 144 个特征有 2D 参考值（506 行）；25 个形态学特征只有 3D 口径，未纳入本轮，不能外推为「通过了 IBSI」。
- **实现覆盖进一步收窄**：本轮只跑数字体模（95 个纹理特征 / 408 行参考值），且 PyRadiomics 未实现 GLDZM 整族（16 个特征），另有 4 个特征在 PyRadiomics 中已弃用、按类启用时不会计算（GLCM `Dissimilarity` / `Sum variance`、NGLDM `Normalised grey level non-uniformity` / `Dependence count percentage`），再加 NGLDM `Dependence count energy`（1 个），数字体模 136 行中只有 113 行有映射。
- **聚合口径还要再砍一半**：IBSI 数字体模的 2D 参考值分三种聚合方式。`2D`（54 行）可由逐层特征求均值复现；`2D, averaged` 与 `2D, slice-merged`（共 82 行）要求在矩阵层面跨层平均或合并，PyRadiomics 只能在单层体积上计算，当前无法重建。
- **数字体模没有公布容差**：手册中数字体模 136 行的容差列全部为 `—`；有容差的 350 行都来自 CT 配置 A/B。因此只跑数字体模只能得到 35 行偏差，**算不出一致率**。要产出 pass/fail 一致率，必须引入 CT 配置 A/B 数据；本轮尚未引入，结果段不得出现一致率。
- **滤波器口径风险**：wavelet / LoG 等滤波器在不同实现间差异较大，需逐项核对，不能默认一致。
- **参数依赖强**：bin width、插值、重采样与掩膜二值化任一变化都会改变特征值，跨环境结果可能不完全相同。
- **无临床含义**：本案例只做特征口径校验，不产出也不应解读任何临床指标。
- **参考值版本已冻结但仍可能更新**：本轮锁定参考手册 v10 的 Chapter 3 页面（源 HTML SHA-256 `5263658a…`）；若官方发布新版本，必须重新提取并记录差异，不能直接把新旧参考值混用。

## 常见问题

**为什么不能写「复现了 IBSI 的 169 个特征」？**
本轮只做 2D 子集，且 IBSI 论文的核心是标准化提案与一致性核验，不是一个可以被「整体复现」的单一实验结果。准确表述是「对 2D 子集逐特征校验参考值一致性」。

**PyRadiomics 参与 IBSI，这个复现还有意义吗？**
有意义，但定位必须准确：它验证的是「平台封装后的特征计算链路是否与参与软件的参考输出一致」，属于链路一致性检查，而不是独立验证。对外文案必须同时写出参与关系。

**特征对不上时怎么处理？**
先定位参数：离散化方式、插值、重采样、掩膜二值化、滤波器类型。若参数完全一致仍不一致，再按滤波器口径、特征定义差异分类记录，不删除不一致样本。

**为什么有偏差数字却没有一致率？**
数字体模的 136 行参考值全部没有公布容差，按预注册规则，无容差行只报告偏差、不判 pass/fail、也不进入一致率分母。本轮可比 35 行因此只做按族偏差汇总；一致率必须在引入 CT 配置 A/B（有容差的 350 行）后另做。

**可以把这个结果用于临床吗？**
不可以。本案例是特征计算口径校验，不涉及任何临床终点，也不构成诊断依据。
