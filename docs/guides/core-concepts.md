# 核心概念

理解下面这些对象，就能顺畅地使用 RadStudio。

## 概念地图

```text
组织 Organization
└── 项目 Project                       ← 权限与配额的最小单元
    ├── 数据资源目录 Data Resources
    │   └── 资源文件 AssetVersion      ← 按内容哈希去重
    ├── 数据集合 DataCollection        ← 可编辑样本表，带修订号
    │   ├── 样本行 Row
    │   │   ├── 影像 / ROI / 矩阵等角色绑定
    │   │   └── 标签与患者标识字段
    │   └── 读取配置 ReaderConfig      ← 带修订号的读取参数
    ├── 工作流 Workflow
    │   └── 工作流版本 WorkflowVersion ← 不可变的流程快照
    └── 运行 Run
        ├── 输入快照 InputSnapshot     ← 集合修订 + 文件清单
        ├── 节点 Node                  ← 一次算子调用
        ├── 事件 Event                 ← 状态与日志流
        └── 产物 Artifact              ← 指标、模型、图表、报告

算子目录 Operator Catalog             ← 可用的节点类型与版本
组织钱包 / 套餐 / 用量                 ← 计算积分与 AI Token
```

## 项目 Project

项目是最小管理单元。数据资源、数据集合、工作流、运行、AI 会话都归属于某个项目，项目归属于组织。

项目成员有三级权限：

| 角色 | 典型权限 |
| --- | --- |
| viewer | 查看项目、数据资源、运行与结果 |
| editor | 上传资源、编辑数据集合、编辑并运行工作流、分享到数据广场 |
| manager | 管理成员、归档项目等管理操作 |

组织层另有 owner / admin / member，用于成员、套餐、积分与组织设置。计费与存储配额挂在**组织**维度，而不是个人。

## 数据资源、集合与读取配置

数据输入由三层组成：

- **资源文件**：上传到项目资源目录的原始文件，按内容哈希去重，不带语义。
- **数据集合**：一张样本表，每一行代表一个样本或一个单细胞文库，行内用角色绑定资源文件（如 `image`/`roi`、`matrix`/`barcodes`/`features`）。集合带修订号，行级变更会递增修订。
- **读取配置**：读取节点的参数，按修订保存。同一集合可以为不同用途保存多套配置。

读取节点（`ReadImages`、`ReadTable`、`ReadSingleCell`、`ReadDicom`、`ReadNifti`）是工作流唯一的输入路径。旧的 `DataInput` 已下线，不再使用「冻结数据集版本」的概念。

运行提交时，平台把集合修订、读取配置修订与文件清单固化为**输入快照**。之后修改集合不会改写已完成的运行；复现时应记录快照哈希。

质控状态按样本记录：`accepted`、`warning`、`blocked`、`excluded`。被阻断或排除的样本不会进入实验。

## 样本与角色

一个样本行对应一个分析单元及其角色绑定：

- **影像**：PNG / JPEG / TIFF / BMP / NPY / DICOM 序列 / NIfTI
- **ROI / Mask**：作为独立角色绑定，或在资源目录模式下按命名规则配对
- **标签**：来自样本表字段，取值按读取配置映射
- **单细胞**：一行可以是一个 10x 文库或一个 `.h5ad` 文件

影像级是首版统计单位，不是患者级。多 ROI 场景下，分析使用哪个 ROI 必须明确，不能静默覆盖旧绑定。

## 工作流与版本

**工作流**是画布上的节点与连线；**工作流版本**是它的一份不可变快照。

一个版本会记录：

- 使用了哪些节点类型与算子版本
- 每个节点的参数
- 节点之间的输入输出连接
- 名称、说明与创建时间

因此，只要工作流版本与输入快照未变，同一工作流再次运行的行为就应一致。修改画布不会影响已经提交的运行；需要变更时保存为新版本。

## 算子 Operator

算子是工作流节点的实现，例如「质量检查」「2D 特征提取」「逻辑回归」。

每个算子有：

- **类型**（如 `QualityControl`）与**版本**（如 `1.0.0`）
- **参数与输入输出**：决定节点如何配置、能连接到哪里
- **执行资源**：由平台按算子类型自动分配，无需用户选择机器

可用算子及版本见算子目录；目录之外的需求见自定义算子开发。

## 运行 Run 与节点

一次**运行**按拓扑序执行工作流中的每个节点。

节点状态机：

```text
pending → running → succeeded
                  ↘ failed
                  ↘ cancelled
```

- 终态不可回退。
- 节点失败会携带错误码，例如 `node.input_invalid`、`node.input_unresolved`。
- 页面会实时显示节点进度与日志；取消会传递给正在执行的节点。
- 重试会基于失败的运行创建新运行，而不是改写历史记录。

## 产物 Artifact

节点输出与最终结果都以**产物**形式记录：文件、清单、指标。产物清单包含路径、哈希与类型，运行详情页可按节点浏览。

常见产物包括：

- `features.csv`、`labels.csv`、`samples.json`
- 模型文件与交叉验证预测
- ROC / 混淆矩阵 / 校准曲线等图表
- `report.html`、`summary.md`、检查清单
- 复现包（含工作流版本、输入清单与可独立运行的 Python 代码）

## 数据广场 Plaza

数据广场独立于项目，承载公开数据集与工作流案例。用户可浏览、引用、导入项目或投稿。每个发布条目都有不可变版本快照、许可协议与审核记录；投稿只接受已完成的运行。

## 计费对象

平台有两套相关的计量：

- **计算积分**：运行按实际消耗的计算资源折算积分；组织预充值或套餐附赠。
- **AI Token**：套餐含周期 Token 额度，超额部分按单价从组织积分扣除。

两套记录都与组织钱包关联，但分账记录，不混用。详见账号与计费。
