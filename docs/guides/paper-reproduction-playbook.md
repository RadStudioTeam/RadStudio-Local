# 如何复现一篇论文：从选题到案例页

本教程给出一条可执行的论文复现路径，目标不是「跑出一个好看的数」，而是产出**可追溯、可复核、边界清楚**的复现记录。全部步骤以 RadStudio 的工作流、运行记录与产物为基础，示例来自已完成的 Scanpy PBMC3k 案例。

如果你还没跑通过工作流，先完成新手教程；需要自定义算子或外部验证时，再看进阶教程。

## 最终要交付什么

一次合格的论文复现至少留下七类材料：

| 材料 | 最低要求 |
| --- | --- |
| 论文登记 | DOI / PMID、期刊年份、复现范围、不做什么 |
| 数据记录 | 来源、版本、许可、下载日期、SHA-256、再分发边界 |
| 工作流 | 工作流版本、算子版本、关键参数、随机种子 |
| 运行记录 | runId、输入快照、镜像/运行时、终态与耗时 |
| 指标产物 | 指标 JSON、逐样本预测、图表源数据，不手填数字 |
| 差异表 | 与原文在数据、架构、超参、划分、口径上的逐项差异 |
| 案例页 | 九段结构，含局限性与常见问题 |

## 第 0 步：选题与冻结范围

先回答三个问题：

1. **复现哪一部分？** 工具论文与临床论文的复现对象不同。例如 Scanpy 论文复现的是官方教程标准流程，不是论文里的全部图表；MedSAM 只复现零样本推理协议，不训练 157 万图像对。
2. **哪些明确不做？** 把「不训练」「不做细胞类型注释」「不声称患者级划分」写进范围，比事后解释更可信。
3. **验收口径是什么？** 指标、容差、一致率、可视化例数都要在看结果前确定。

把这三项写进论文台账后再动手。台账模板随复现包维护；内部篇目登记不在本仓发布。

> **范围冻结的判断标准**
>
如果一句话里出现「顺便再看看」「多试几个参数凑一下」，说明范围还没冻结。复现是验证协议，不是调参竞赛。

## 第 1 步：核验数据与许可

对每个数据集记录：

- 官方来源 URL 与版本号（例如 10x PBMC3k v1.1.0、hg19）。
- 下载日期与文件 SHA-256，归档字节数。
- 许可条款：是否允许再分发原始文件、是否仅限研究用途、是否需要数据使用协议。
- 去标识化状态；若含患者信息，不得上传或进入复现包。

三条硬规则：

1. **许可不清的数据只做本地复现**，仓库与复现包不分发原始文件。
2. **禁止再分发的数据**（如 Dataset B Release Agreement）只保留派生结果与复现脚本。
3. **私有数据**不得进入公开案例、论文与复现包。

数据入库后建立数据集合，让读取节点绑定集合而不是临时目录，这样输入快照才能被运行记录固定。

## 第 2 步：把论文方法翻译成算子链

按「读取 → 质控 → 预处理 → 建模/分析 → 评估 → 报告」拆解，每一步都问：

- 论文里的这一步，平台有没有对应算子？版本是多少？
- 参数是否在算子契约里？没有的话，是固定写死还是需要新版本？
- 论文的描述是否足够精确到可执行？不精确的地方必须进入差异表，而不是自行补成「看起来合理」的值。

以 Scanpy PBMC3k 为例，实际链路为：

```text
ReadSingleCell 1.1.0
  → ScQualityControl 1.0.4
  → ScNormalize 1.0.3
  → ScDimReduction 1.0.3
  → ScClustering 1.0.3 / 1.0.4
  → ScDifferentialExpression 1.0.3
  → Report
```

对应参数（`minGenes=200`、`maxGenes=2500`、`maxMitoPercent=5`、`targetSum=10000`、`hvgCount=2000`、`nComps=50`、`neighborsK=10`、`resolution=1.0`）全部来自运行记录，而不是教程页面的文字描述。算子版本与参数清单可在算子目录核对。

需要自己实现算法时，走自定义算子开发。新增或修改算子必须先完成双份 `operators.json` 同步与单测，再进入正式运行。

## 第 3 步：运行并固定证据

一次正式运行至少要能回答：

- 用的是哪个工作流版本？改过参数后是否产生了新运行？
- 每个节点的算子类型与版本是什么？
- 随机种子、划分文件、输入快照哈希是什么？
- 运行时镜像或 Python / 依赖版本是什么？
- 终态是成功、失败还是部分成功？失败节点与重试记录在哪里？

操作上：

1. 在工作台完成节点连线与参数配置，先做结构校验。
2. 用小样本或合成数据试跑，确认端口类型与产物写回。
3. 再对全量数据提交正式运行，运行完成后立即导出运行摘要与关键产物。
4. 把 runId、工作流版本、算子版本、参数与产物哈希登记到案例页或复现包清单。

> **不要用「最新版本」描述方法**
>
「最新版 Scanpy」不是可复现标识。论文、案例页与复现包都必须写明确切版本号。

## 第 4 步：对照、验收与稳定性

### 1. 先写差异表，再谈结果

差异表至少覆盖：输入与预处理、模型/算法、超参数、划分方式、训练预算、指标口径。差异不是失败，隐瞒差异才是。

### 2. 指标只从产物读取

准确率、AUC、Dice、ARI 等数字必须来自 `metrics.json`、`predictions.*`、`seg-metrics.json` 或运行摘要。不允许：

- 从论文原文抄一个数字当成本次结果；
- 用截图或手算补齐缺失指标；
- 在未完成时填占位数字。

### 3. 复现的是协议，不是某一个点

单细胞、深度学习和随机划分都对版本与种子敏感。合理的验收方式是：

- 主结果完成一次全量运行；
- 关键随机环节做稳定性扫描（不同 seed / resolution / 折）；
- 报告波动范围，并说明扫描覆盖得仍然很窄。

### 4. 用 P4 的真实结果理解「一致」与「不一致」

Scanpy PBMC3k 案例的公开产物显示：

| 项目 | 结果 |
| --- | --- |
| QC 前 | 2700 cells × 32738 genes |
| QC 后 | 2638 cells，与教程公开值一致 |
| Leiden `resolution=1.0` | 9 簇（教程约 8 簇） |
| 第 9 簇 | 12 个细胞，marker 为 PPBP、PF4、SDPR、GNG11 |
| seed 43 相对 baseline | ARI 0.9146 |
| seed 44 相对 baseline | ARI 0.9106 |

这些数字都能在案例页与运行产物中回指。案例没有把 9 簇改写成 8 簇，也没有宣称 UMAP 逐点一致，而是解释差异来自 HVG flavor、PCA 维数、Leiden 参数与未做 `regress_out`。完整记录见Scanpy PBMC3k 案例。

## 第 5 步：按九段结构写案例页

推荐固定九段，缺一段就不算完成：

1. **复现对象**：题目、作者、期刊年份、DOI、复现范围、不做什么。
2. **论文数据与结果**：只复述原文公开口径，并标明「以原文为准」。
3. **本次数据**：来源、版本、样本量、许可、校验和。
4. **工作流与算子**：链路图、逐节点版本与参数。
5. **方法差异**：逐项列出与原文不同之处及影响。
6. **复现步骤**：让别人能按步骤重跑。
7. **复现结果**：运行登记、指标表、图表与产物路径。
8. **局限性**：版本敏感、样本限制、能力边界、不可外推的结论。
9. **常见问题**：解释最容易被误读的数字或差异。

写作时把「未完成」写清楚。例如复现包尚未发布，就写「复现包与 DOI 待发布」，不要填占位 DOI，也不要在 landing 卡片上填数字。已上线的案例可作为模板参考：BUSI 影像组学、IBSI 2D、Kermany 胸片、MedSAM。

## 第 6 步：复现包与干净环境重跑

复现包至少包含：

```text
manifests/      数据清单与校验和（不含受限原始数据）
splits/         划分文件与 hash
predictions/    逐样本预测
metrics/        指标 JSON 与图表源数据
figures/        图表
workflows/      工作流版本与参数快照
environment/    运行时、依赖版本、镜像摘要
reproduction/   重跑脚本与说明
```

导出后在一台干净环境重跑一次，并记录：

- 重跑日期与环境；
- 与原运行的差异（数值、产物哈希、失败节点）；
- 差异原因（依赖版本、硬件、随机性）。

**没有干净环境重跑，就不能把复现包标成「可独立复现」。** 当前 P4 的复现包发布与独立重跑仍在进行中，因此案例页不登记 DOI。

## 第 7 步：发布与口径审核

对外发布前逐条检查：

- [ ] 数字与运行产物一致，且能指到具体文件。
- [ ] 未完成项标「进行中」，没有占位数字。
- [ ] 没有「临床可用」「超越论文」「逐位一致」「SOTA」等表述。
- [ ] 写明了数据许可与再分发边界。
- [ ] 写明了能力边界（例如单细胞不做细胞类型注释、批次整合、双细胞识别）。
- [ ] 至少两人独立核对过文案与数字。

宣传语只描述「复现了什么协议、得到什么可追溯结果」，不描述「达到什么临床性能」。

## 常见问题

**论文没给全超参数，怎么办？**

按公开信息能确定的部分固定，无法确定的部分在差异表中列明，并说明采用了什么替代设置。不要伪装成原文设置。

**结果和论文不一致，是不是失败？**

不一定。先确认数据、划分与指标口径是否对齐，再看差异是否可解释。复现的目标是协议可追溯，而不是把数字凑到与原文相同。

**能不能只跑一次就发布？**

可以发布「已完成一次真实运行」的案例，但必须同时标注未做的稳定性、复现包与独立重跑。不能把单次运行写成「已验证可复现」。

**没有 GPU 能做深度学习复现吗？**

可以降级为推理或小样本微调，但案例页必须显著标注「非完整训练复现」，不能与完整训练结果混为一谈。

**复现包能包含原始数据吗？**

只有在许可明确允许再分发时才可以。多数医学公开数据仅限研究用途或要求签署协议，复现包应只含清单、校验和与获取脚本。
