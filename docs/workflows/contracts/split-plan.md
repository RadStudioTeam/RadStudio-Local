# 来源绑定划分计划 v1

状态：开发分支已实现 radstudio/split-plan@1 的 Go/SDK 实际文件校验，以及 DataSplit@1.2.0、HoldoutSplit@1.2.0、ValidateFeatureTable@1.0.0。业务栈和生产未部署；不代表真实 FC 已验收。已有算子定义、旧工作流和旧产物不自动改写。

## 组合路径

既有特征提取 → 特征表验证 → 分组交叉验证（来源绑定）或留出集划分（来源绑定）。

验证节点接收 legacy 特征表，检查实际字段、样本键、行宽及数值/缺失值，成功后原样透传同一引用，并明确声明 feature-table@1。它不补零、不拟合变换，也不证明特征单位或算法经过 IBSI 参考验证。新版划分要求显式特征表声明；旧输出不能直接假称已经验证，应插入验证节点。

CV 参数为 folds（2—10）、randomSeed；留出参数为 validationRatio、testRatio、randomSeed、stratify。用户需要已知 0/1 标签，患者和样本身份不得为空白，本版本沿用患者级目标假设，同一患者标签必须一致；同患者多影像具有不同目标标签的任务需要另行定义目标单位和算子版本，不能改患者 ID 绕过。缺失特征值不妨碍按身份/标签划分，也不会被偷偷填补；后续训练仍须满足其缺失值与最小样本要求。

新版留出支持 validationRatio=0，仍提供三个集合和三张特征表，空验证表保持为空。旧版本计算路径保持原行为。训练/测试必须非空，实际算法还检查类别和分组数量；内容结构通过不能代替数据画像或科研可行性预检。

## 引用和身份

```json
{"method":"StratifiedGroupKFold","seed":42,"source":"file:features.json#sha256=<SHA256>;type=feature_table","identityHash":"<身份摘要>","folds":[{"fold":0,"trainIds":["i2","i3"],"testIds":["i0","i1"]},{"fold":1,"trainIds":["i0","i1"],"testIds":["i2","i3"]}]}
```

source 必须是指向特征表的可移植工作区引用，禁止 URL、绝对路径、越界、符号链接及非普通文件。文件校验一次有界读取来源，再对同一批字节计算 SHA-256 和校验内容，不先哈希另一次读取的文件。不搜索任意宿主目录。输出阶段允许来源位于本节点输出或已暂存输入；恢复阶段重新检查同样的来源。

identityHash 对来源 records 按原顺序取 imageId/patientId/label，以既有精确规范化 JSON 编码后计算 SHA-256。特征值不参与身份摘要，但仍完整参与来源文件哈希。重排行后应重新生成划分；成员始终按 imageId 匹配，不用行号猜测。不能通过逐图改名 patientId 掩盖实际患者重叠。

来源必须通过 feature-table@1，样本集合和标签身份须与计划精确一致。样本标识最长 255 字符，与 `dataset_samples.image_id` 列宽同宽（理由见 `sample-collection.md` 的「样本键宽度为什么统一收成 255」）；成员列表最多 200000 项；文件最大 64 MiB、深度 64，继承科学数字文本/指数预算，支持 1e-200。参数的展开位数预算不套到来源科学特征值。

## CV 结构与来源规则

method 固定 StratifiedGroupKFold，seed 为 0—2147483647 整数。folds 为 2—10 项，编号从 0 连续且唯一；每折训练/测试 ID 均非空、无重复且互斥。各折样本全集相同；测试折不能重复取样，合起来覆盖全集。绑定来源后，全集须等于来源 imageId 集合，标签须已知，训练/测试 patientId 集合互斥，同一患者多张图必须留在同一侧。

该校验确认计划成员和患者隔离，不独立重演所声称的随机算法，也不证明预处理或模型从未额外读取测试数据。seed/method 的声明不等于算法来源资格。

## 留出结构与来源规则

```json
{"scheme":"holdout","seed":42,"stratified":true,"source":"file:features.json#sha256=<SHA256>;type=feature_table","identityHash":"<身份摘要>","partitions":{"train":["i0","i1"],"validation":[],"test":["i2","i3"]}}
```

三个列表都必须存在，训练/测试非空，验证可以为空；样本互斥且合起来覆盖来源，集合间患者也互斥。stratified 记录算法配置，不凭该布尔值宣称分布已满足统计要求。CV 与留出字段不能混用；未知额外元数据可以保存，但不视为已验证科研语义。

## 调用与错误

validate_content_bytes 只检查结构及计划内部约束；validate_content_file 和实际节点边界额外核验来源字节、身份、完整覆盖、标签一致性与患者隔离。不能以纯内存结构检查代替来源绑定。

/source 定位来源引用、路径、文件哈希、样本覆盖或标签身份问题；/identityHash 表示身份摘要不匹配；/folds/N 和 /partitions/test 等定位分组重叠。非法目录或不可读文件也保留 /source，不输出宿主绝对路径。来源特征表自身的结构问题保留其内容契约位置。

SDK 边界转换为 operator.input_invalid / operator.output_invalid；Go 发布和恢复独立执行相同校验，失败阻断该节点登记。修复应回查来源版本、患者标识和成员列表后重新生成，不能删除检查字段或关闭规则掩盖问题。

## 版本、迁移与兼容

迁移 045 仅插入三个新版本；当前种子目录原有 25 份定义经精确数字比较保持不变。独立测试库已验证迁移与重复执行；业务库及生产未应用。新增登记使用 Docker runtime，没有虚构 FC 绑定或任意 -fc 别名。交付时 API/worker、目录及 SDK 执行镜像须一致更新。

回滚应用时保留新版本及历史引用，可停用新版本供新建运行选择；不要删除已有记录或重写旧定义。旧工作流继续锁定旧版本。旧训练消费者的 JSON 身份算法可能区分 1 与 1.0，而新身份采用精确数字归一化；目前完整回放验证覆盖常规整数标签，其他编码需要显式兼容或新版训练消费者，不能静默改旧语义。

验收包括共同结构/来源案例、患者泄漏、同患者矛盾标签、空白身份、缺失/篡改文件、合法科学极小值、Go 执行后恢复及真实 Go→SDK HTTP/bundle/v2 回执。完整 40 份合成影像的新旧流程和独立重放另在实施记录保存结果。它们不代表真实 FC/GPU、自定义代码隔离或全部训练节点内容契约化。
