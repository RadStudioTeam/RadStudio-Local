# 数据与运行资源授权

状态：当前实施分支 A0 检查点；内部开发/验收文档，不直接发布到客户文档站。

资源归属必须从持久化对象沿关联解析，不能相信请求附带的 projectId/datasetId。项目有效角色沿既有组织/项目成员规则计算。

| 入口 | 最低角色 | 归属来源 |
| --- | --- | --- |
| 数据集列表 | viewer | 请求项目须先鉴权 |
| 数据集详情与嵌套 GET（版本、样本、文件树等） | viewer | 数据集 → 项目 |
| 数据集非 GET 操作 | editor（更高门槛由具体处理器保留） | 数据集 → 项目 |
| 数据版本冻结 | editor | 版本 → 数据集 → 项目 |
| QC 验证写入 | editor | 版本 → 数据集 → 项目，并要求请求 datasetId 一致 |
| QC 状态与报告 | viewer | 版本 → 数据集 → 项目 |
| 工作流版本独立读取 | viewer | 工作流版本 → 项目 |
| 运行读取/列表及子资源 | viewer | 运行 → 项目 |
| 运行执行/取消/重试 | editor | 运行 → 项目 |

无权访问返回 403；不存在资源返回 404；QC 请求中的 datasetId 与版本不一致返回 400，且不得重写报告。拒绝冻结/删除不能改变原始资源。账号登录、微信绑定和组织成员身份本身不代替项目权限检查。

本批数据/QC 修复基于旧分支提交 75f19110 的已审阅实现，以文件级三方补丁迁入；未引入其 AGENTS/任务历史，也未替换当前更严格的运行绑定、原子预扣与重试保护。旧测试结果只作参考，当前分支重新跑全量验证。

验收覆盖 outsider/viewer 读写矩阵、列表与详情、冻结和删除拒绝、错误 QC 绑定及拒绝后的版本/数据/报告保持。测试中的直接处理器调用与正式路由调用边界不同，授权入口以 HTTP 路由为准。尚需继续审计上传、单独文件下载等其他入口，不能据此宣称全部资源授权审计完成。
