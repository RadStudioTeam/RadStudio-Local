# 分片来源与合并证据

新捕获的运行规则包含 `shardSources: 1`，依赖 `invocationExecution: 1`。旧快照缺失该字段时维持旧行为，不补写字段或改变摘要。

## 已实现

特征提取、深度学习训练与推理进入多分片执行前，从基础输入目录重新读取绑定的样本清单。要求引用唯一、路径安全、实际字节 SHA-256 与绑定引用一致、JSON 无重复字段或尾随内容；单份来源 JSON 上限 64 MiB、深度上限 96。允许同一引用的端口别名，拒绝多个不同的同类来源。

重新读取的样本集合必须与传入派发计划的路径、数量及完整编码内容一致。训练还重新读取 split_plan 的 folds，要求 2—1024 个唯一的 0—1023 整数编号，并与待派发折集合一致。此检查不代替 split-plan 内容契约的科学语义验证。

失败归因为 `operator.source_invalid`，保留请求 ID、`fieldPath` 与 `rule: shard-sources/1`，不输出宿主机路径。预检失败不调用执行器。

## 调用前门禁

并行派发前，从绑定来源生成私有、只读的分片证明计划，不将其暴露给执行器。每个子调用在实际执行前核对分片编号、数量、样本范围或训练折、推理偏移、全部直接输入及其暂存文件哈希。额外输入也拒绝，不仅校验已知端口的子集。计划在各分片间共享只读数据，避免每个子调用重新解析完整来源清单。

合并调用执行前，按分片编号核验指定已登记产物和合并输入字节。调用前、发布前、恢复复验复用相同规则；调用前失败不进入执行器。旧快照未声明 `shardSources` 时保留旧行为。

## 发布与恢复门禁

节点产物登记前，依据基础绑定来源重新计算每片样本范围或训练折分配，核对实际派生调用的全部直接输入、推理偏移及输入文件字节。合并请求的 part 端口必须对应该编号分片恰好一次登记的指定产物，类型、哈希与大小均独立复验；合并暂存文件也重新验哈希。训练合并另保留全部基础输入。模型权重等大文件采用流式哈希。

恢复时对持久化后回读的调用证据使用同一验证器。合法来源可复用已完成调用；分片或合并文件丢失、篡改时拒绝恢复，发出 `run.restore_failed` 与 `operator.source_invalid`，不静默重派发。恢复因此要求保留分片输入、输出及合并输入工作区。该门禁不信任调用自身重算出的摘要来证明其来源。

## 尚未完成的验收边界

调用前校验仍与实际执行存在时间间隔。复制期的字节核验与写隔离由 [分片输入的写隔离](input-isolation.md)（`input-isolation/1`）承担：分片输入改为私有副本、复制同时验绑定哈希、整份工作区扇出仅在执行器能证明输入只读时才用硬链接，非普通条目拒绝派发。两者合起来仍不构成为不可信 Python 提供操作系统/云端级隔离与文件不可变性的完整证明，也不将本门禁描述为自定义算子隔离资格。直接文件哈希一致不证明影像、模型权重或递归清单内容的完整科学语义，也不证明模型拟合数据血缘或云端实际镜像身份。上述完整验证仍待后续工作。

单分片路径保留既有执行校验。本地测试不代表真实阿里云 FC 资格；真实 FC 隔离执行、权限验证和完整使用/开发/契约/运维文档仍为开放门禁。

## 验证与回滚

三种算子分别覆盖解析计划被替换、绑定来源字节被替换，共六项拒绝执行回归；另有三类算子的 18 项持久化证据回读与篡改测试，以及完整 worker 的发布阻断、合法恢复不重派发、篡改恢复拒绝测试。Go 全量回归（隔离 PostgreSQL/Redis 与实际 SDK 桥接）22.924s 通过，vet 与 9 份契约、18 个副本一致性检查通过。新增三类算子的直接输入损坏零派发测试，以及派生编号/额外输入拒绝测试通过。尚未进行该检查点的真实云端执行。

回滚应回退该检查点的代码及三份同步运行快照 Schema；新规则已持久化的运行不可由不理解该规则的旧版本继续执行。不得通过删除旧运行字段来伪造兼容。
