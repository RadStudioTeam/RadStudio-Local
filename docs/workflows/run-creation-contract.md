# 运行创建与资源授权契约

状态：A0 实施检查点，2026-10-27。本文面向内部开发和测试，不在 SaaS 对外文档站发布。

## 创建运行

`POST /api/v1/runs` 要求请求项目 editor 权限。工作流版本及其所属工作流均必须属于该项目。数据版本由工作流快照的 DataInput 绑定推导；请求省略 datasetVersionId 时使用该绑定，提供时必须命中派生集合，否则返回 422，错误码 dataset.mismatch、字段 datasetVersionId。

新建前调用工作流校验器重新检查结构、算子版本、参数、数据归属和冻结状态、执行目标。校验失败返回 422 ValidationResult，发生在计费、并发槽和运行入库之前。多个 DataInput 各自绑定数据版本，运行按节点隔离暂存，详见 [多数据源运行](multi-dataset.md)；单体执行模式显式拒绝多数据源，不做静默降级。

config 的 imageDigest、workflowId、targetNodeId 是平台控制字段，请求包含任一个时返回 400；执行目标使用顶层 targetNodeId。其余 config 参数参与幂等请求比较。

## 幂等请求

键命中后，仅当项目、发起者、工作流版本、有效数据版本、执行目标、默认化重试上限及用户 config 均一致，才返回 200 和原运行。缺省或非正 maxRetries 沿用默认 3。原运行的镜像摘要保持不变，重放不重复扣费，也不依赖当前镜像环境配置。

键被其他请求使用时统一返回 409，不返回已存在运行的 ID 或内容。仓储故障返回 503，不能当作键不存在继续创建。内存和 PostgreSQL 仓储对未命中统一返回 ErrRunNotFound。

运行、资源限制、组织预扣余额和 consume 流水由 CreateReserved 在同一事务提交；不再先扣费再依赖退款补偿。PostgreSQL 同键并发由唯一索引确定创建者，其余请求读取该已提交运行并重新比较请求；请求一致返回 200，否则统一 409。不同键对同一余额的扣减也必须满足非负条件。资源限制或流水写入失败时整体回滚。内存实现使用统一锁顺序提供相同原子边界。

Redis 并发槽属于独立系统：同时请求仍可能因套餐并发上限返回 409，此时可用同键重试；本检查点不宣称 Redis 与数据库之间具备分布式事务。数据库提交结果未知和进程退出后的槽位恢复仍需后续审计。

## 读取和操作

运行详情、列表、事件、日志、产物、快照、节点、流式读取要求所属项目 viewer；取消、重试、执行要求 editor。独立工作流版本读取要求其项目 viewer。计费明细除项目权限外保留组织权限限制；无组织历史运行也不能跨项目访问。产物文件下载已有项目权限检查继续生效。

## 验证证据

合成项目/用户的 HTTP 与 handler 回归覆盖跨用户读取、角色矩阵、操作拒绝、工作流版本读取、请求不一致、非法数据和目标、扣费前拒绝、真实创建后的幂等重放及积分不重复扣减。已恢复独立 Docker/PG/Redis 环境，既有全量集成测试通过；新增创建路径的 PG 同键并发、计费故障注入与容器科学工作流端到端仍待补。真实阿里云 FC 验收属于总体发布门禁，本文不代表该门禁通过。

事务证据：两个独立 PostgreSQL 连接池发起 16 个同键请求，只创建一条运行、一组限制和一笔预扣；余额不足及扣费后限制 INSERT 故障整体回滚；两个不同键竞争不足以同时预扣的余额，仅一方成功，另一方余额不足。相同并发断言覆盖内存实现。

## 重试运行计费

失败或取消的运行在重试时创建独立子运行，保留原工作流、数据、镜像摘要和资源限制，记录 parentRunId。新运行清空 settledCredits、settledAt、历史 CU 和成本；按资源限制重新预估积分，申请并发槽后通过 CreateReserved 原子提交。新预扣流水只引用子运行，父运行账单不变。

重试余额不足返回 402，并发上限返回 409。原子创建失败时不留下新预扣；失败槽位清理使用独立的 5 秒超时上下文，不依赖已取消的 HTTP 上下文。队列写入失败仍由持久化 pending 运行恢复，不重复创建子运行。

内存及 PG 测试覆盖已结算父运行重试后的独立预扣、父账单保持、子运行未启动取消后的全额退款、重复结算不重复退款；内存另覆盖无余额时不创建子运行及 HTTP 402。重试已在预扣之前检查项目/计费组织一致性、工作流及其版本项目归属、数据与工作流绑定、冻结数据归属、固定镜像摘要、目标节点及完整现行工作流规则。错误返回 422 ValidationResult，提供 code、fieldPath 和 message。重试接口的显式幂等规则见下文；新运行已有冻结快照时沿用冻结定义与执行策略，无快照历史运行仍按现行确定性规则校验，不将归档定义的恢复能力泛化到所有历史记录。

重试错误示例：run.workflow_project 定位 workflowVersionId；dataset.mismatch 定位 datasetVersionId；run.image_unpinned 定位 config.imageDigest；run.target_invalid 定位 config.targetNodeId；run.billing_org_mismatch 定位 orgId。数据归属/冻结和不存在目标沿用工作流校验器的字段级问题。以上失败均发生在组织额度、槽位及子运行写入之前。


## 重试幂等请求（A0.7）

`POST /api/v1/runs/{id}/retry` 可传 JSON：

```json
{"idempotencyKey":"retry-unique-action-key"}
```

接口先按持久化父运行检查项目 editor 权限。键最多 255 UTF-8 字节，不能包含空白或控制字符。正文上限 8 KiB、深度上限 8；只接受对象和该字符串字段，拒绝重复字段、未知字段、null、尾随正文。旧版空正文、空对象或空键仍表示每次发起独立重试，不承诺幂等。

键使用现有运行表全局唯一索引，与创建运行共用命名空间。命中时核对发起者、项目、父运行、工作流及数据版本、重试层级、重试上限和完整继承配置；不匹配返回 409 且不返回已有运行内容。查询故障返回 503，不继续创建。原子插入的竞争失败者释放自己申请的槽，再做相同身份与语义核验。

同键成功重放返回 201 和同一子运行的当前状态，即使该子运行已取消或结算，也不创建新子运行、不重新预扣、不重复写入 run.queued 或队列。合法重放不重新执行新建预检。新的、有意发起的重试使用新键。重试上限继续按现有父子层级计数，本改动不把同一父运行的不同键限制成单个子运行。

客户端应在用户发起一次重试动作时生成并保存键，遇到网络超时、503 或单槽竞争 409 时保留原键；不得自动换键再提交。只有用户明确发起另一轮独立重试才生成新键。当前小程序客户端已接入持久化键及重复请求合并；其他旧客户端或外部 API 调用方仍需自行遵守该生命周期。

同键并发请求仍可能在赢家提交前因套餐单槽上限收到 409。槽位拒绝后服务端复查已提交赢家；若尚未提交，客户端稍后用原键重试。幂等不绕过套餐限制。数据库提交结果不明、Redis 计数恢复及进程崩溃窗口仍未由本检查点解决。

验证覆盖：内存与两个独立 PostgreSQL 连接的并发同键请求及单槽竞争后重放；仅一份子运行、预扣和入队事件；已结算重放不扣费；跨用户/跨父运行冲突；快速查询失效后事务竞争失败者仍核验身份；查询故障关闭、UTF-8 字节预算及歧义正文拒绝。全量结果记录于实施任务清单。


## 小程序键生命周期（A0.8）

本地记录键为服务地址、账号 ID、父运行 ID 的组合，不包含患者数据或凭据。随机标识使用微信 `getRandomValues` 的 16 字节结果（基础库至少 2.15.0）；生成失败时不降级为无键提交。POST 之前必须成功存储并回读验证，读取/写入失败或记录损坏均不发送请求、不静默换键。未确认的记录不设自动过期。

同一进程内的重复请求合并为一个 Promise。网络错误、4xx/5xx、响应无法确认和进程重载均保留原键。响应前后检查账号和服务未切换，避免旧请求跨会话派发或跳转。成功后的子运行标识可供「查看重试运行」使用；成功确认写盘失败仍保留已确认结果及原键，但禁止另建，直至用原键重放并保存成功。

「另建一次独立运行」仅在已确认子运行并完成本地记录后可选，弹窗再次提示独立预扣和计费；新键在发送前取代已确认记录。新一轮结果再次未知时继续复用该新键。已有请求确认中不能并发另建。主动清理设备数据、不同设备或并行独立客户端之间不提供共享本地意图；服务端的相同键幂等仍有效，但不能凭不同键识别同一用户意图。

验证命令：`pnpm --filter @radstudio/mini test:retry`（11 项，执行实际 API 和 Page 模块的行为测试）、`pnpm --filter @radstudio/mini typecheck`。设置 `RADSTUDIO_MINI_NODE` 为 Node 可执行文件后，Go 全量中的 `TestMiniRetryHTTPBridge` 启动隔离 HTTP 服务并执行真实客户端模块：首次服务端已创建但客户端丢失响应、模块重载、并发重放、显式另建和再次重载，共五次 HTTP 请求仅创建两次有意子运行及两笔预扣，每个子运行只有一条入队事件。

上述测试不代替微信开发者工具或真机验收。本机尚未验证实际微信存储/随机 API、WXML 渲染和导航行为；完整发布门禁保留。该检查点不解决数据库未知提交归因或 Redis 槽恢复。


## A0.9：提交确认丢失与并发槽恢复

PostgreSQL COMMIT 返回异常不再一律等同于回滚。除明确的事务回滚外，使用独立于请求取消的 5 秒上下文，按本次生成的运行 ID 查询主库，并核对发起者、项目、工作流和数据版本、幂等键、配置、预扣及重试字段。匹配时返回已创建的运行；记录不存在、查询失败或内容不匹配均保留未知状态，避免把仍在提交中的事务误判为失败。

无法确认时，创建与重试接口返回 HTTP 503，JSON 包含 `code=run.commit_unknown`、中文提示及 `runId`，保留本次并发槽。客户端应保留原幂等键核对，不自动更换键创建。内部数据库错误不向客户端输出。

并发槽的持有权可核对：占槽成功后写 `org:{orgID}:runs:slot:{runID}`（值为占槽时刻，存活 24 小时），释放以 `org:{orgID}:runs:released:{runID}` 的 `SET NX` 作闸门，因此终态钩子与恢复扫描竞争同一运行时只减计数一次，计数键也不会被压成负数。后台任务每 5 分钟按持有权标记扫描，只处理占槽已超过 90 秒提交宽限窗的条目，并一律以运行真相为准：运行不存在（预留随事务回滚或已删除）与已进入终态（钩子未跑到）回收，运行仍活跃或查询失败保持占用。恢复不会解除未知提交本身的保守占用，只把已被数据库否证的槽位收回。

已验证：内存及独立 PostgreSQL/Redis 的 Go 全量回归（18.764s）、vet；真实事务提交后注入确认丢失并取消请求，仍恢复原运行、重放不重复预扣；明确回滚无运行记录；查询失败、缺失及身份/配置/预扣不符的未知分类。HTTP 创建与重试的未知结果均断言计数保留且 `runId` 有持有权标记、显式释放后归零；释放一次语义、提交宽限窗、回滚回收、活跃保留、终态回收与查询故障保留各有定向用例。故障注入在真实 COMMIT 返回后执行，尚不等同于数据库网络层丢包测试。

待补：数据库网络层故障注入、进程崩溃与 Redis 分区的运维演练，以及计数键在运行仍活跃时过期导致的超额放行（Redis 写入失败的占槽没有持有权标记，只能靠 24 小时 TTL 兜底）。保守占用的额度仍可能被长时间持有，不能视为完整恢复机制验收通过。真实 FC、完整文档和 A—F 总门禁保持未完成。


## Web 客户端键生命周期（A0.10）

Web 端与小程序同构：`apps/web/src/lib/run-intent.ts` 以 `radstudio:run-intent-v1:{kind}:{scope}` 为存储键，把随机标识与（重试）已确认的子运行 ID 存在浏览器 `localStorage`。创建作用域为账号、项目、工作流版本、数据版本与目标节点；重试作用域为账号与父运行。作用域只含标识，不含患者数据或凭据。

发送前必须写入并回读验证，写入失败或回读不一致直接取消提交，绝不发无键请求。记录损坏时抛错要求人工核对或清除站点数据，不静默换键。除服务端明确宣告「幂等键已用于其他请求」（409）外，任何失败（网络错误、超时、5xx、响应丢失）都保留原键，下一次点击重放同一请求。同一作用域的并发点击合并为一个 Promise。

创建成功后立即删除该作用域的意图记录；重试成功后把子运行 ID 记入同一记录。运行面板据此在进入父运行时先读本地记录：已确认子运行即显示「上次重试已创建运行 · {id}」并提供「查看该运行」，同时禁用「重新运行」并给出原因标题；只有显式点「另建一次运行」才换一把新键，且换键前必须已有确认到的子运行 ID，否则提示先查询上次结果。账号为空（未登录）时拒绝提交，避免把运行归属到错误账号。

边界：`localStorage` 只在本机本浏览器有效，跨设备、无痕会话与用户清除数据均会换新键；服务端仍按相同键幂等，但无法凭不同键识别同一用户意图。AI 结果解读的 `createRunAnalysis` 仍使用一次性随机键，不在本检查点范围内。

验证命令：`cd apps/web && node --test`（75 项，含 13 项意图键行为用例）、`npx tsc --noEmit`、`pnpm --filter web lint`；浏览器验收 `RADSTUDIO_WEB_URL=http://127.0.0.1:3010 npx playwright test e2e/run-intent.spec.ts`（4 项）：真实 Chromium 下第一次提交被连接重置后本地仍持有原键、第二次提交的线上载荷与第一次逐字节相同、成功后跳转子运行、回到父运行出现确认条且重试按钮禁用并带原因标题、显式另建才换新键；对照用例用改造前的「点击时现生成 UUID」方式走同一采集管道，两次载荷必然不同，证明断言非空转；窄屏 390×844 断言 `scrollWidth-innerWidth=0` 并截图。路由拦截为合成后端，不替代真实账号下的端到端验收。
