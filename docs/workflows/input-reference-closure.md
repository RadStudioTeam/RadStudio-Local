# 输入间接引用闭包

节点输入除了直接绑定的产物引用，还可能通过 JSON 清单里的路径字段（`imagePath`、`roiPath`）或内嵌产物引用字符串指向工作区内的其他文件。本契约规定这些间接引用如何被展开、检查与物化。

## 传递闭包

`walkRefClosure` 从节点直接输入出发做广度优先展开：清单引用到的条目若本身是 JSON 且字节可得，就继续展开它引用的条目，直到没有新条目。展开是传递的，因此「清单 → 清单 → 影像」这种嵌套结构与「清单 → 影像」在检查与物化上同等对待。

收敛与规模边界：

- `seen` 集合让引用环与重复引用只访问一次，自引用或互引用不会导致无限读取。
- 被展开的 JSON 清单份数上限 4096（`refClosureDocumentLimit`），超限报 `manifest reference closure exceeds 4096 JSON documents` 并阻断派发。影像等叶子条目按引用计数进入集合、不计入该上限，避免大样本集（每例数个路径字段）被误拒。
- 无法取得字节的条目按叶子处理而不是失败：数据集挂载条目在本地没有副本；预检因此不能穿过挂载清单继续展开，只能在该清单被物化到下游工作区之后再复验。

## 派发前预检

`preflightNodeInputs` 在写入输入工作区、派发云函数之前，对闭包内每个条目做就近解析（祖先输出目录按图距离优先，其次数据集挂载）。全部缺失项一次性汇总为 `node <id> input preflight failed: N unresolved reference(s) [...]`，归因 `node.input_unresolved`。改造前只展开一层：被引用清单自身再引用的影像在预检阶段是「看不见」的，只能等算子执行中途报缺。

## 跨节点物化

`transferManifestRefsWithMounts` 按同一闭包把条目复制到下游输入工作区：复制（或按预签名/挂载对象取回）之后立即回读该文件，若是 JSON 就继续展开，所以嵌套影像与嵌套清单一起落到下游工作区，不再出现「上一层清单已复制、下一层引用悬空」。挂载模式下条目只登记进 `mountInputs` 并去重、不回读字节，因此该分支要等条目被物化到下游工作区之后才复验；逐片闭包沿用同一分工（见下节）。

引用文件的内容校验沿用既有分工：产物引用字符串由下游算子 `read_bytes` 按引用内 SHA-256 校验；`imagePath`/`roiPath` 这类路径字段没有内容寻址来源，本契约只保证传递保真与存在性，不声称证明影像字节身份或影像几何语义。分片侧的绑定来源哈希核验见 [分片来源与合并证据](shard-sources.md) 与 [分片输入的写隔离](input-isolation.md)。

## 逐片闭包

分片把节点输入拆成每片自己的私有工作区，因此每片要按自己的样本表重新算一遍闭包（`shardInputClosure`），三个集合各自负责一件事：

- `keep`：本片够得着的全部条目，用于按片过滤数据集挂载输入——挂载条目只在片间保留自己样本引用的那些。
- `stage`：其中在节点输入目录确有普通文件副本的条目，才复制进分片私有工作区。挂载条目在本地没有副本，由挂载点直读，强行按 `keep` 复制会在暂存阶段报缺。
- `bound`：每个条目的来源哈希。直接输入引用与闭包内**嵌套的产物引用**都自带哈希，复制的那一瞬间核验；`imagePath`/`roiPath` 路径字段没有内容寻址来源，不进这张表，因此不会被伪绑定。

改造前每片只算一层：深度学习推理收样本体内的路径字段与产物引用，特征分片连路径字段都不收。因此「样本表 → ROI 清单 → ROI 影像」的嵌套影像既不会被落进分片工作区，也不会保留在挂载输入里——本地非挂载模式下算子执行中途报缺，云挂载模式则整片丢失按约定直读的 ROI。嵌套产物引用的篡改同理只能等算子 `read_bytes` 才暴露，现在提前到复制时报 `input-isolation/1` 并归因 `operator.source_invalid`。

特征分片刻意不按 `keep` 裁剪挂载输入：算子可能读取样本表未列出的数据集文件，云路径维持整份只读挂载，因此该分支只新增私有副本集合。

## 尚未覆盖

- 穿过数据集挂载的清单嵌套引用无法在派发前展开（本地无字节），只能待物化后复验；分片侧同样如此——挂载条目里的 JSON 清单没有本地副本，其内部引用的条目对闭包不可见。特征分片不裁剪挂载列表，整份只读挂载仍能直读；深度学习推理按 `keep` 过滤挂载条目，这类「只有挂载清单知道」的影像不会被保留，因此该分支要求样本表把影像直接列在自己的路径字段里。
- 路径字段引用的文件内容不受哈希绑定保护：与节点输入共享工作区的写隔离已由 `input-isolation/1` 承担，但上游算子写入错误影像不构成可检出的契约违规。
- 闭包递归只覆盖派发前预检、跨节点物化与逐片暂存三处；进程重启后的节点恢复（`validateRestoredArtifactEvidence`）只逐条比对直接输入引用字符串，既不重读字节也不重扫清单，因此间接条目在恢复后不再经过闭包检查。

## 验证

`services/api/node_inputs_test.go` 新增：闭包展开嵌套清单且不触及无关清单、引用环终止、清单份数上限、预检报出嵌套缺失（`605_roi.png`）且不误报已解析项、跨节点物化把两层嵌套文件一并落到下游工作区、环状链物化终止。非空转对照由 `TestLegacyOneLevelExpansionMissesNestedRefs` 承担——它在测试内按改造前的单层展开算法跑同一夹具，旧算法认为引用全部可解析（缺失集为空），而新预检拒绝派发。既有跨祖先解析、缺失聚合、挂载满足预检、流式复制清单引用等用例继续通过。

逐片闭包由 `workspace_isolation_test.go` 覆盖：三层输入（路径字段 + 内嵌产物引用 + 清单里的清单）全部进 `keep`、只有本地副本进 `stage`、路径字段不获得哈希绑定、嵌套引用被换字节后在复制时报 `/inputs/masks.json` 隔离失败、互引用清单终止收敛、符号链接清单在展开前即拒绝。非空转对照 `TestLegacyShardKeepSetMissesNestedInputs` 在测试内逐字复现改造前特征分片的集合计算，旧集合既收不到嵌套清单与影像，也收不到样本自己的路径字段影像。端到端由 `TestExecuteShardedFeatureNodeFansOutAndMerges`（每片只落自己的影像/清单/嵌套影像，且不含其他分片文件；假算子对路径字段影像做存在性检查）与 `TestExecuteShardedDLInferenceNodePrunesAndMerges`（每片挂载输入恰好覆盖本片样本的影像 + 嵌套 ROI，并逐片校验 ROI 清单的保留与裁剪）承担。
