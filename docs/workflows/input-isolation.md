# 分片输入的写隔离

规则标识 `input-isolation/1`，失败归因 `operator.source_invalid`。它约束「算子或并发分片能否改写权威输入字节」，与 [分片来源与合并证据](shard-sources.md) 的 `shard-sources/1`（来源绑定与派发前预检）互补：预检证明「派发那一刻的字节是绑定的来源」，写隔离证明「此后没有任何一方能把它们换掉」。

## 隔离的两条通道

**选择性私有暂存。** 特征提取与深度学习推理按样本范围扇出，每片只把该片引用的条目复制成自己的私有副本（`stageShardWorkspace`）。复制写入 `<目标>.staging`，流式复制同时得到实际 SHA-256，与绑定哈希一致才 `unlink` 目标再 `rename` 发布；不一致则删除暂存文件并失败，未经验证的字节不会留在分片工作区。这关掉了「预检通过 → 使用之间」的竞态窗口：预检后有人改写来源时，复制期得到的哈希就不再匹配。

**整份工作区扇出。** 深度学习训练每个折都要看到全部样本，仍需要整份工作区（`stageFullWorkspace`）。只有当执行器能证明输入目录对算子只读时才用硬链接零拷贝，否则退化为逐文件私有副本——正确性优先于零拷贝。

## 拒绝跟随克隆存活的非普通条目

节点工作区内的符号链接、管道、设备等非普通条目一律拒绝派发：私有暂存逐条要求来源是普通文件（`workspaceSourceFile`），整份工作区遍历对每个非普通条目失败（「节点工作区含非普通文件，拒绝派发」）。链接不会随克隆进入分片，因此也无法借分片目录把写入引到别处。

## 写入一律换新 inode

分片与合并工作区里的文件写入走「写临时文件 → `unlink` 目标 → `rename`」（`replaceWorkspaceFile`，经 `writeWorkspaceFile` 使用）。`os.WriteFile` 的原地截断在目标与节点输入共享 inode 时会连带改写权威输入字节；先 `unlink` 保证任何一次写入都只影响分片自己的目录项。

## 执行器能力门禁

`IsolatesInputs()` 是执行器自愿声明的能力，未实现该接口的执行器（含测试替身）按「不隔离」处理，因而只会拿到私有副本：

- Docker 执行器声明隔离。容器把 `/task` 整体可写挂载（`invoke.json`、`result.json` 落在其中），再用更具体的绑定把输入目录以 `:ro` 覆盖在 `/task/<输入目录名>` 上，实测向该目录写入返回 `Read-only file system`。当前 serve 路径的输入实际来自 `invoke.json` 内的打包副本并解到临时目录，该只读绑定属纵深防御。
- 云执行器声明隔离。输入经对象存储以独立副本传输，只读挂载不可回写。
- `implementationCheckedExecutor` 与计量包装器逐层转发内层执行器的判定，不会因为包一层就丢掉能力。

## 失败表述

`workspaceIsolationError` 的错误串以 `input-isolation/1:` 开头并携带 RFC 6901 输入指针；指针逐段转义（`~` → `~0`），嵌套路径仍按目录层级可读，例如 `data~x/a b.json` → `/inputs/data~0x/a b.json`。失败细节的 `rule` 为 `input-isolation/1`，`operatorErrorAttribution` 归为 `operator.source_invalid` 并保留请求 ID，不输出宿主机路径。隔离失败发生在派发之前，不调用执行器；分片失败按既有语义取消兄弟片并保留首次观测到的根因。

## 尚未覆盖的边界

本契约只解决「输入被改写」这一类，不构成不可信代码的完整隔离资格：

- 宿主机文件系统权限仍是根依赖。分片私有副本不再回写节点输入，但没有对副本追加 `chmod` 只读位——开发宿主为 Windows，POSIX 权限位不起作用且会干扰后续 `RemoveAll`；容器侧由 `:ro` 绑定与 `--network none`、资源限制承担。
- 扇出结束后不无条件复算节点输入目录的完整哈希。大影像按每片数十 GiB 流式重读代价过高；私有暂存已在复制期逐条验证，每片派发前另由来源门禁（`shardSourcePlan.validate`）对全部直接输入重读哈希。发布与恢复门禁只覆盖输出产物与直接引用字符串，不重读节点输入字节。
- 正在进行的同步文件写入仍是协作式取消，不承诺即时中断。
- 真实阿里云 FC 的实际镜像身份、RAM 权限与隔离行为仍未验收，本地 Docker 与单元回归不能代替。

## 验证

`services/api/workspace_isolation_test.go` 11 项：私有暂存不回写节点输入、复制期哈希不一致时拒绝且不留下被篡改字节、符号链接拒绝、RFC 6901 指针层级、非普通条目拒绝派发、能力门禁（含 docker/云/两个包装器）与归因/细节规则。非空转对照由 `TestHardlinkTruncateWriteReachesNodeInput` 承担——它在测试内按改造前的「`os.Link` 克隆 + `os.WriteFile` 原地截断」写法复现节点输入被改写的旧行为，同时证明 `replaceWorkspaceFile` 会断开共享 inode。

失败优先证据：改造前该用例暴露的缺陷依次是「被篡改的来源仍被暂存」（先写目标后校验）、`/inputs/data~1link.json` 这类整串转义破坏层级、以及 `stageFullWorkspace` 未先建目标根目录导致 DL 训练分片读不到顶层 `samples.json`（`filepath.Walk` 跳过根条目）；第三种只有嵌套条目的用例本会空转，故现用顶层文件 + `os.Stat` 断言固定。Go 全量回归（独立 PostgreSQL 55434/Redis 6382 与实际 SDK 桥接）ok 16.617s、vet 与 9 契约/18 副本检查通过。

## 回滚

回退本检查点即恢复「整份硬链接克隆后裁剪」的扇出与原地截断写入：分片将重新与节点输入共享 inode，复制期校验与能力门禁一并消失。`input-isolation/1` 不写入运行快照字段，故不存在新旧快照兼容问题，但旧版本无法维持新版本已隔离运行的字节一致性承诺。
