# 冻结执行规则与运行策略（快照 v2）

## 已接入的行为

新运行快照升级为 v2，将执行规则标签和调度/默认资源策略一起纳入摘要。运行创建后，后台更改这些已冻结字段只影响新工作，不改变该运行或其重试的已保存值。创建限额从同一策略上下文生成，不在快照之后重新读取实时默认值。运行配置的 imageDigest 与快照默认镜像保持一致。

v1 的无标记标准 JSON 摘要和带 radstudio-cjson/1 的精确摘要继续可读；不把旧记录重写为 v2 或补造规则证据。没有快照的运行继续明确标为 legacy。损坏快照的公开来源标记为 invalid-snapshot，不因为存在一个字段就显示已冻结。

## 规则标签

当前支持：parameterDialect=radstudio-parameters/1、parameterExecution=1、implementationSelection=exact-v1、orchestrator=node-orchestrator/1、portSemantics=legacy-semantic/1；新捕获快照另含 artifactBoundary=1、contentContracts=1；内容规则 1 必须同时启用产物边界，旧缺省规则保持兼容。历史缺省产物规则继续兼容，新的产物执行与恢复检查见 [产物边界](artifact-boundary.md)。声明不同规则时返回 run.execution_rules_unavailable，不能按当前默认规则解释它。规则标签不是代码签名；未来兼容适配必须显式实现和测试。

## 冻结策略

- 默认 runner 镜像摘要。
- 特征分片（1–32）、每片进程（1–16）、检查点间隔（1–1000）、进度间隔秒数（5–600）。
- CNN 训练分片（1–16）与推理分片（1–64）。
- 默认 CPU、内存、磁盘、超时和本地网络配置。

这是当前实现的策略范围，不代表 FC 实际配额。CPU 必须能解析为正有限数，避免 NaN、无穷或非法文本在计费时静默回退。内存/磁盘固定当前原始字符串，派发与重试检查限额行一致；本批不证明单位规范、物理容量、套餐额度和云规格全部可用，这些仍属资源预检与云资格门禁。

镜像默认值为空时，可保留未配置的内部元数据快照；创建可执行运行、派发和重试必须有固定的默认镜像。Docker 算子的空镜像在捕获时填入默认摘要；非空但可变的镜像标签拒绝。未知运行时不按 Docker 默默处理；HTTP 绑定要求合法 HTTPS（回环调试可 HTTP），不能包含 URL 用户凭据。

runtimeEvidence 只描述声明状态：declared-image-digest、endpoint-only、unconfigured 或 unverified。HTTP endpoint-only 不构成不可变函数版本或真实部署证明。数据传输/异步开关、实际云函数资源、价格与套餐、批准环境完整版本、后台设置全局事务版本等不在本批冻结字段内，不能把本批策略当作完整环境或价格合同。

## 创建、派发和重试

创建仍使用现有 CreateReserved 原子边界，资源限额、运行和预扣一起写入。本批没有恢复旧的先扣费/再创建路径。新快照包含 v2 策略，改变策略会改变摘要；幂等重放仍按原运行返回，不因后台配置变化产生额外扣费。

worker 在执行前验证快照版本、规则、摘要、策略、镜像与资源限额。资源行不存在时，可从冻结策略在本次执行中构造限额；查询服务失败不能当作不存在。无效数据在派发前写入稳定错误码和运行失败说明，取消/已终态记录不被覆盖。

重试保留父快照，独立估算并原子预扣。原限额存在但与冻结策略不一致时拒绝；明确缺失时从冻结策略创建子运行限额；查询故障时返回 503，不创建子运行、不写消费流水。策略/限额不一致返回结构化 422，带 resourceLimits 或快照字段定位。

执行上下文缓存绑定具体运行对象，不因另一个对象使用相同 run ID 就复用校验。切回旧版/无快照运行时清除另一运行的策略上下文。内存限额的创建和读取复制结构体，调用方保留引用不能修改保存值。

## 错误与恢复

run.snapshot_invalid 表示快照损坏或格式不支持；run.execution_rules_unavailable 表示 worker 不支持已声明规则；run.policy_invalid 表示策略值无效；run.image_unavailable / run.image_mismatch 表示默认镜像缺失或与快照不一致；run.operator_image_unpinned / run.runtime_unavailable 表示节点执行绑定不可用；run.resources_mismatch / run.resources_unavailable 表示限额不一致或存储暂时不可读。

格式或规则错误应部署兼容 worker 或重新预检创建运行，不能直接改写历史快照绕过。资源服务故障恢复后再重试。后台修改默认值不用于“修复”既有冻结运行；需要新配置时创建新运行并重新确认其含义和成本。预检确认与策略摘要绑定尚待 C/F 接入，当前不宣称已有跨确认失效保护。

## 验证与未完成门禁

定向测试覆盖配置变化使新摘要改变、旧运行保持原进程/分片/超时、两类 v1 兼容、精确数值和大图、规则/策略/镜像失败闭环、终态保护、上下文隔离、资源缺失恢复、查询故障/不一致时拒绝且无扣费、无效执行绑定、限额引用隔离和非法 CPU。

真实 PG JSONB 精度往返、原子预扣和 HTTP SDK 桥接纳入 Go 全量回归。当前只交付冻结规则与部分策略；完整调用回执仍须绑定请求标识、参数值、控制值、输入与分片记录。独立复现包、实际内容验证、批准环境和真实阿里云 FC 执行/权限/隔离验收、完整使用/开发/契约/运维文档继续作为总方案强制门禁。

无数据库迁移、生产部署或云资源操作。新增 Schema 的唯一来源为 packages/operator-schema/run-operator-snapshot.schema.json，同步脚本目前校验六份契约/十二份副本。回滚到只支持 v1 的 worker 前应检查是否存在 v2 运行，不能让旧代码静默读取不支持的规则。

最终验证：Go 全量独立 PG/Redis 与实际 SDK HTTP 桥接 15.370s、vet、六份契约/十二份副本检查通过；补验久排队但未启动的无效快照运行全额且仅退款一次。本批没有修改 SDK 执行代码，SDK 全量 209 项记录保留在 B8，不把旧记录算作本批新验收。


## 连续均衡样本分片（B17a）

新捕获快照增加 rules.shardPartition=balanced-contiguous/1，依赖 invocationExecution=1。该标签属于 Go 节点编排规则，不传成 SDK 单体目录的额外未知规则；单体执行没有 Go 样本扇出。未知布局拒绝，不以当前默认布局解释。没有该字段的历史快照仍使用原向上取整布局，读取和重新序列化不补字段、不改变摘要。

布局用于特征提取和 CNN 按样本推理；训练按折的已有分组算法保持原样。新布局将 N 个样本划为 min(请求片数,N) 个非空连续片：前 N % 片数 个片各多一个样本，任意两片数量最多差 1，保持原顺序且完整覆盖。10 个样本请求 8 片时得到 2、2、1、1、1、1、1、1，而非旧算法实际生成的 5 个两样本片。推理的 shardOffset、挂载过滤和最终全局样本顺序须对应实际范围。

冻结策略中的分片数是配置上限，executionControls.shardCount 记录实际生成的片数。旧布局可能少于请求上限；例如旧 10/8 仍保留五个连续两样本片，但实际控制和回执记录 5，不以 8 误判为缺少调用。修改计数不能改变旧输入边界或重写旧事件。新布局在正常调度的已钳制范围内，实际片数等于配置请求；空集合和单片继续使用普通调用路径。

验证包括非整除样本的实际特征扇出/合并、6 个样本请求 4 片的真实 Go 推理调度（挂载、偏移及全局预测顺序）、新旧完整 worker 控制/回执记录、旧快照摘要往返、未知布局/依赖拒绝，以及 1—127 样本和 1—64 请求片数的完整覆盖性质。该规则修复布局与实际片数，不等于已经独立核验每条派生样本或 fold 的科研来源；来源验证、递归模型/清单、FC 真实资格和资源预检仍须继续完成。
