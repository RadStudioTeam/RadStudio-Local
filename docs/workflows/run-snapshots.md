# 运行级算子快照（当前检查点）

本说明描述当前分支的服务端实现，不代表自定义算子已开放。完整交付范围仍以工作流扩展方案及任务表为准。

## 创建与执行

创建运行先校验项目、工作流与冻结数据绑定，再从注册中心解析精确版本。当前云优先配置可能选择同版本的 `-fc` HTTP 变体；所选执行定义随后冻结，不能在派发时重新选择最新版本。冻结后的实际定义再参与工作流校验，避免公共定义与运行时变体端口、参数不兼容而在扣费后才失败。

`config.operatorSnapshot` 为服务器保留字段，用户提交时 HTTP 400。快照与运行配置、限制和预扣通过现有 `CreateReserved` 原子创建；快照生成或校验失败发生在扣费之前。幂等请求比较排除服务器快照，保留原有发起者、项目、版本、数据和用户配置比较。

每个条目保存节点 ID、请求 type/version 和实际执行的完整注册定义（含端口、参数、默认值、资源及运行绑定）。Token 不写入快照。新运行存在快照时始终按节点派发，即使进程配置为 monolith；避免整图兼容路径绕过冻结版本。

HTTP 执行时按原算子 ID 获取当前 Token，允许凭据轮换，但完整执行语义绑定必须与快照一致。已下线或归档不会修改历史定义，也不会阻止快照运行。普通运行 API 不返回内部快照和执行端点，仅增加 `operatorProvenance: snapshot-v2 | snapshot-v1 | legacy | invalid-snapshot`。服务端保存的配置不受响应裁剪影响。

## 摘要和精度

当前新快照为 `version: 2`、`canonicalization: radstudio-cjson/1`，增加 rules/policy；摘要覆盖整个快照（digest 替换为空字符串后）的规范化 JSON。规则及策略见 [v2 执行策略](run-execution-policy.md)。旧带标记 v1 仍按 nodes 计算规范化摘要。对象键排序，数字以十进制数学值规范化，因此 JSONB 把 `1e2` 改写为 `100` 不改变摘要，9007199254740993 与 9007199254740992 仍不同。此算法是 RadStudio 自有规范，不能标称为 RFC 8785。

读取预算为 16 MiB、96 层、最多 500 节点；规范化拒绝重复键、非法 UTF-8、未配对 Unicode 代理项、超出支持范围的数字和尾随 JSON。数字处理的限制以 `json_contract.go` 为准（最多 128 位有效展开数字、指数绝对值最多 308、原始数字最多 256 字符）。未知版本、未知规范化算法、摘要不匹配和节点身份不匹配拒绝执行；v2 不支持的规则或失效策略也拒绝派发。未带 canonicalization 的旧 v1 沿用原有标准 JSON 摘要；没有快照的运行明确标为 legacy，仍走既有精确目录解析。

运行的内存复制使用深拷贝，PG 配置读取使用 `UseNumber`，不会通过 float64 损失已经捕获的精度。不可 JSON 编码的内存配置在持久化或扣费前拒绝。

边界：B6 已修复注册中心 PG、工作流请求和草稿/冻结版本等服务器路径的精度损失，见 [服务器数值边界](json-precision.md)。B4 接入受控参数核心后，冻结定义的验证视图已改为精确深拷贝，不再转为浮点数。当前检查点证明快照边界内往返精度，不声称任意参数从输入到所有 SDK 的精确数值闭环已经完成。

## 重试与兼容

有快照的重试使用冻结定义校验工作流；项目、组织、工作流归属、数据冻结及归属、执行目标和镜像摘要仍实时检查。子运行保留原快照，独立预估与原子预扣，父运行结算不被覆盖。损坏快照返回结构化 `run.snapshot_invalid`；无快照的旧运行不会自动获得历史证明，仍须通过当前目录校验。
