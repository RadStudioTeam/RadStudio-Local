# 算子版本归档

## 使用

管理后台先将版本下线，再选择归档。归档保留端口、参数和版本定义，便于历史工作流显示；不会从数据库删除。归档后不可恢复、不可编辑、不进入新增目录。重用能力应发布新的版本。

历史可读不等于可新运行：工作流校验只接受 available；归档版本不能创建新方案运行。运行级快照尚待交付，当前不能宣称已创建但未派发的运行不受归档影响。

## API 与存储

保留 DELETE /api/v1/admin/operators/{id} 路径兼容，成功仍为204，语义改为 deprecated→archived。审计操作名为 operator.archive。重复归档或非下线版本返回409，未知ID返回404。

迁移 041_operator_archive 扩展 status CHECK（与既有 041_admin_roles 分别记账，不能互相覆盖）；不改写既有数据。PostgreSQL与内存仓储保留版本唯一键，不能用相同 type/version 重新注册覆盖历史。

## 部署与回滚

先在隔离库验证041，再备份目标库并迁移，然后发布API/admin；本阶段未部署开发或生产API。

旧后台不认识 archived，不能直接回滚应用并保持该状态。应优先前向修复；若必须回退，先停管理写操作、备份、将 archived 显式映射为 deprecated、再恢复旧约束及旧应用，同时禁止物理删除入口。该映射会丢失归档终态，必须记录并在重新升级时恢复，不能静默进行。

本检查点同时接入 042_operator_immutable：普通 SQL DELETE 也被拒绝，归档不能修改、恢复或直接跳过下线步骤。后续完整 draft/构建/验证生命周期与运行快照仍未交付，不能将归档当作自定义代码云资格。

## 验证

TestOperatorArchivePreservesDefinition 对内存与隔离PG验证历史保留、目录排除及禁止修改/恢复；TestAdminArchiveRetainsVersion 验证管理接口归档与409行为。


当前管理界面已验证编辑字段只读、归档无恢复按钮和下线→归档刷新。浏览器测试复现旧 request<void> 对成功 204 继续解析 JSON 导致报错和列表不刷新，已明确处理空响应；最终两项合成管理端浏览器回归通过。
