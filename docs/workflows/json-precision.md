# 工作流参数的服务器 JSON 数值边界

## 已验证的路径

服务器工作流请求、管理员算子注册/更新使用 `UseNumber` 解码动态 JSON 数值。内存工作流复制采用先检查 JSON 可编码、再深拷贝的方式；工作流草稿、冻结版本、分享 IR、模板和注册中心 Schema/默认值的 PG 读取显式保留 `json.Number`，避免 pgx 默认扫描到结构体时隐式经过 float64。广场工作流原始 IR 导入使用相同的数值解码辅助函数。

例如 9007199254740993、0.10000000000000001 在这些服务器路径中保留原值。数字在 JSONB 中可能改变书写形式，但不会被应用转成邻近浮点数。冻结版本与分享读取仍深拷贝，调用方修改不会改变保存的工作流。分享的 IR/Layout 继续 `json:"-"`，不因复制方式改变而出现在普通响应中。

不可 JSON 编码的内存草稿、更新和分享在改变存储前返回错误。失败更新不会增加草稿 revision。PG 的无效 JSON 写入继续由编码和事务边界拒绝。

## 发布不可变与等值数值

算子发布后的定义仍不可变。比较首先处理完全相同的 JSON；表示不同但可规范化的数字按同一十进制语义比较，因此 `100`、`100.0`、`1e2` 等价，与 PostgreSQL JSONB 比较一致。字符串 "100" 不等于数值 100，9007199254740993 不等于 9007199254740992。这个比较同时用于 HTTP 快照执行绑定校验。

允许按既定规则更新名称、说明和凭据，不因等值数字的表示差异被误拒绝；实际端口、参数值、执行地址或其他执行语义变化仍要求新版本。旧定义完全相同的序列化内容保留既有比较行为，不因元数据操作获得新发布或执行资格。

`decodeJSONNumbers` 是普通 JSON 精确解码辅助函数，不是完整契约验证器。参数仍须经过受控 Schema、大小/深度/数值预算校验；不能以“解码成功”替代发布、运行或云资格验证。

## 证据与剩余边界

回归先复现 HTTP 解码、内存复制、真实 PG 草稿/冻结版本/注册读取、分享和广场导入的精度损失，再验证修复。补充真实 PG 模板往返、精确阈值比较、允许的元数据更新、分享隐藏快照、非法草稿/分享无副作用断言。B6 全量独立 PG/Redis Go 回归 12.116s，vet 通过，无数据库迁移。

这不保证浏览器原生 JavaScript Number 能表达超出安全整数范围的输入；编辑器原始参数录入、AI 工具参数转换和所有外部服务入口还需分别验收。也不把服务器保留十进制参数等同于训练算法使用无限精度计算。B8 已接入 [Python HTTP 冻结定义校验、控制分离和 Decimal 传输](execution-contract.md)；代码/环境不可变绑定及完整调用回执尚未完成；B7 的精确版本选择与自报见 [执行版本](execution-version-resolution.md)，真实 FC 门禁保持。

本批 PG 夹具只使用独立测试库，草稿、版本、分享和临时模板按唯一合成 ID 清理；已发布注册版本遵守归档不删除的历史约束。
