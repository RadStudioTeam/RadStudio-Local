# 分片失败与取消（B17b）

开发分支的特征提取、CNN 按折训练和按样本推理共用失败收敛机制。它只改变失败与取消的处理，不改变成功任务的布局、折分配、内容契约、冻结摘要或调用计费规则。没有数据库迁移或 Python 协议变更。

## 首次观测到失败后

每个分片退出时，先检查暂存/编码/执行错误、空结果或非 completed 结果。首次观测到的失败在并发安全记录器内保存，然后才取消兄弟片。所有分片退出后，父节点取该记录进行错误归因；不会按数组索引先挑到兄弟片的 context canceled。

该顺序也覆盖 SDK 返回 status=failed 但调用函数 err=nil 的情况：立即发出取消信号，不等待其他长任务到外层超时。空结果视为明确失败，不允许继续合并。暂存和编码提前返回都经过相同路径，不存在先取消、后丢失原始错误的分支。

返回的原始错误用 %w 包装，保留 errors.Is/errors.As 和错误链；SDK 失败结果保留错误码、消息、报告的请求 ID/FC 请求 ID 及字段位置。父节点继续使用既有单一终态写者，将其保存到 node.failed；不发布该节点产物和 node.completed，不执行合并。

多个分片可能独立失败，本机制记录的是 worker 首次观测到的失败，不宣称找到了唯一因果根源或还原了云端发生时间。底层每次调用的运行用量/调用审计仍按既有路径保存，父节点诊断不等于全部云端重试或完整 FC 资格证明。

## 真正的取消

外层用户取消、worker 停止和节点超时仍使用原有归因优先级，不把真实取消伪造成输入错误。若首次结果本身是 SDK cancelled，保留其取消状态及说明；纯 context.Canceled/DeadlineExceeded 不改写，组合错误链也不拆掉原始原因。

入口已经取消时，立即返回，不清空原输出/分片诊断目录，也不派发。各兄弟片在暂存前及派发前再次检查取消，减少无效工作；已经开始的文件系统操作仍是协作式取消，不承诺能即时中断每次文件拷贝。临时诊断文件保留不等于产物已经发布，仍遵循原有保留/清理策略。

## 验证与边界

三类实际 Go 扇出回归使用可控执行器，让低索引分片等待取消，高索引分片返回原始传输错误、SDK 失败或空结果；均需保留原始错误，不等外层超时、不进入合并。暂存编码失败、真实取消和组合错误链另有覆盖。完整 worker 测试核对持久化的原始错误码、请求 ID、FC 请求 ID、字段位置，且失败节点没有产物或完成事件；预先取消时核对旧诊断文件仍在及派发次数为零。

上述合成结果不证明实际阿里云 FC 已停止、权限正确或费用已对账，真实 FC 执行/取消/隔离与完整文档仍为开放门禁。独立派生样本/fold 来源、合并引用及递归模型/清单校验仍需后续实现；该修复不能替代科研来源验证。
